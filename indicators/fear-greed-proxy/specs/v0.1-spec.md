# Shiori Fear & Greed Proxy v0.1 規格書

## 1. 指標定位

Shiori Fear & Greed Proxy 是一個 TradingView / Pine Script 指標，目標是在 TradingView 圖表中建立一個接近 CNN Fear & Greed Index 精神的市場情緒代理指標。

本指標不宣稱能 100% 複製 CNN Fear & Greed Index。CNN 原版的完整資料源、標準化方式、歷史校準參數與部分處理細節並未完全公開，因此本指標的正確定位是：

> CNN-like Fear & Greed proxy：可解釋、可調參、可疊圖、可拆解的市場情緒溫度計。

本指標的核心目的不是提供買賣訊號，而是協助使用者判斷市場是否處於極端恐懼、極端貪婪、情緒背離或風險姿態錯位。

## 2. 設計目標

### 2.1 主要目標

1. 在 TradingView 中建立 0–100 分的 Fear & Greed proxy line。
2. 使用七個因子盡量模擬 CNN Fear & Greed Index 的原始精神。
3. 每個因子都能被拆解檢視，避免只給一個黑箱分數。
4. 支援資料缺漏時的降級處理與重新配權。
5. 支援使用者調整 lookback、權重與資料 symbol。
6. 提供 dashboard 顯示總分、狀態、七因子分數與資料品質。

### 2.2 非目標

1. 不宣稱與 CNN 原始指數數值完全一致。
2. 不作為獨立進出場訊號。
3. 不預設自動交易策略。
4. 不將所有市場狀態簡化成單一情緒分數。
5. v0.1 不處理多語系發布文案，該項保留至 v1.0。

## 3. 七大因子架構

本指標參考 CNN Fear & Greed Index 的七項構成概念，並在 TradingView 可用資料限制下建立 proxy。

### 3.1 Market Momentum

概念：衡量 S&P 500 是否明顯高於或低於中期均線。

建議 metric：

```text
momentum_metric = (SPX close / SMA(SPX close, 125) - 1) * 100
```

建議 symbol：

```text
SP:SPX 或 AMEX:SPY 或 CME_MINI:ES1!
```

解讀：

- 數值越高，市場動能越強，偏貪婪。
- 數值越低，市場動能越弱，偏恐懼。

### 3.2 Stock Price Strength

概念：衡量市場中創 52 週新高的股票是否多於創 52 週新低的股票。

理想 metric：

```text
new_high_low_metric = NYSE 52W highs - NYSE 52W lows
```

TradingView 可能限制：

TradingView 不一定穩定提供 NYSE 52 週新高 / 新低資料，因此 v0.1 先定義為可替換資料槽。

候選 proxy：

```text
USI:NHNL 類 symbol（若可用）
RSP / SPY relative strength
sector breadth proxy
```

解讀：

- 新高多於新低，偏貪婪。
- 新低多於新高，偏恐懼。

v0.1 要求：

此因子必須設計為可替換 symbol，不可將單一 symbol 寫死。

### 3.3 Stock Price Breadth

概念：衡量整體市場上漲參與度，而不只看大型股指數。

候選 metric：

```text
advance_decline_metric = advances / max(declines, 1)
或
breadth_metric = cumulative advance-decline proxy
或
rsp_spy_metric = RSP / SPY relative strength
```

建議第一版 proxy：

若 advance / decline 資料不穩，v0.2 prototype 可先使用：

```text
breadth_metric = RSP / SPY
```

解讀：

- 等權重指數強於市值權重指數，代表參與度較廣，偏貪婪。
- 等權重指數弱於市值權重指數，代表市場集中化，偏恐懼或結構脆弱。

### 3.4 Put / Call Options

概念：衡量選擇權市場是否過度避險。

候選 symbol：

```text
CBOE:PCC
CBOE:PCALL
其他 TradingView 可用 put-call ratio symbol
```

建議 metric：

```text
put_call_metric = put_call_ratio
```

解讀：

- Put/Call ratio 越高，代表避險需求越高，偏恐懼。
- Put/Call ratio 越低，代表市場較樂觀或投機，偏貪婪。

標準化方向：

此因子為反向因子，需做：

```text
put_call_score = 100 - normalized(put_call_metric)
```

### 3.5 Market Volatility

概念：衡量市場波動是否異常升高。

建議 symbol：

```text
CBOE:VIX
```

建議 metric：

```text
vix_metric = VIX close
```

可選進階 metric：

```text
vix_metric = VIX / SMA(VIX, 50)
```

解讀：

- VIX 越高，恐懼越高。
- VIX 越低，市場越安逸或貪婪。

標準化方向：

此因子為反向因子，需做：

```text
vix_score = 100 - normalized(vix_metric)
```

### 3.6 Safe Haven Demand

概念：衡量股票相對避險資產的需求強弱。

候選 metric：

```text
safe_haven_metric = SPY / TLT
或
safe_haven_metric = SPY / IEF
```

解讀：

- 股票相對債券越強，偏貪婪。
- 債券相對股票越強，偏恐懼。

v0.1 建議預設：

```text
SPY / IEF
```

原因：IEF duration 較 TLT 溫和，較不容易被單純長端利率波動扭曲。但應保留使用者改成 TLT 的選項。

### 3.7 Junk Bond Demand

概念：衡量信用風險偏好。高收益債越強，市場越願意承擔風險。

候選 metric：

```text
junk_metric = HYG / IEF
或
junk_metric = JNK / IEF
或
junk_metric = HYG / LQD
```

解讀：

- HYG / IEF 越強，偏貪婪。
- HYG / IEF 越弱，偏恐懼。

若 TradingView 可取得 high yield spread 類資料，也可作為進階選項；但 v0.2 prototype 先以 ETF relative strength 為主。

## 4. 標準化方法

每個因子最終都需轉為 0–100 分。

```text
0   = 極端恐懼
50  = 中性
100 = 極端貪婪
```

### 4.1 v0.1 預設：Percentile Rank

第一版建議採用 rolling percentile rank。

```text
score = percentile_rank(metric, lookback)
```

優點：

- 跨資產尺度較容易統一。
- 使用者直觀理解：現在位於過去 N 天的相對百分位。
- 適合 TradingView Pine Script 實作。

缺點：

- 對極端歷史區間敏感。
- lookback 設定會明顯影響結果。

### 4.2 可選：Z-score 模式

後續版本可加入 Z-score 模式。

```text
z = (metric - sma(metric, lookback)) / stdev(metric, lookback)
score = clamp(50 + z * sensitivity, 0, 100)
```

v0.2 prototype 不一定要納入，但程式架構應避免寫死，方便日後擴充。

### 4.3 反向因子

以下因子需反向：

```text
Put / Call Options
Market Volatility
High Yield Spread（若未來使用 spread 而非 ETF ratio）
```

反向公式：

```text
score = 100 - normalized_score
```

## 5. 權重設計

### 5.1 預設權重

v0.1 採七因子等權。

```text
default_weight = 1 / 7
```

### 5.2 使用者可調權重

每個因子應提供 input weight：

```text
w_momentum
w_strength
w_breadth
w_putcall
w_vix
w_safehaven
w_junk
```

### 5.3 Auto Reweight

若某項資料為 na，提供自動重新配權模式。

```text
final_score = sum(score_i * weight_i for valid factors) / sum(weight_i for valid factors)
```

若有效因子數低於最低門檻，總分應顯示 na 或標示資料不足。

建議最低有效因子數：

```text
min_valid_factors = 4
```

## 6. 資料缺漏與降級模式

### 6.1 Strict Mode

只要任一核心因子缺資料，總分顯示 na，dashboard 標示缺漏因子。

適合校準與嚴格研究。

### 6.2 Auto Reweight Mode

忽略缺資料因子，依剩餘有效因子重新配權。

適合一般使用。

### 6.3 Proxy Lite Mode

允許使用較粗略 proxy，例如：

```text
RSP / SPY 取代 market breadth
HYG / IEF 取代 high yield spread
SPY / IEF 取代 safe haven demand 原始算法
```

dashboard 需標示資料品質為 Lite。

## 7. 指標輸出

### 7.1 主線

顯示 0–100 的 Fear & Greed Proxy line。

```text
plot(final_score)
```

### 7.2 區間定義

```text
0–25    Extreme Fear
25–45   Fear
45–55   Neutral
55–75   Greed
75–100  Extreme Greed
```

### 7.3 視覺區域

副圖中可畫出水平參考線：

```text
25, 45, 55, 75
```

並以背景區塊淡色標示不同情緒區域。

v0.2 prototype 可以先保守處理，避免 plot 數量過多。

### 7.4 Dashboard

Dashboard 應顯示：

```text
Total Score
Current Regime
Valid Factors Count
Data Quality: Full / Proxy / Lite / Insufficient
Momentum Score
Strength Score
Breadth Score
Put/Call Score
VIX Score
Safe Haven Score
Junk Bond Score
```

Dashboard 預設放右上角或右下角，提供 input 調整位置。

## 9. Pine Script 實作注意

### 9.1 request.security

所有外部 symbol 應使用 request.security 取得。

時間週期建議預設為日線：

```text
request.security(symbol, "D", close)
```

即使使用者在 intraday 圖表，也應以日線資料計算情緒分數，避免 intraday noise。

### 9.2 na 防護

每個因子都必須有 na 防護。

```text
is_valid = not na(score)
```

不得因單一 symbol 缺資料導致整個 script 報錯。

### 9.3 plot 數量控制

v0.2 prototype 優先顯示 final score。

七因子拆解可用 input 控制：

```text
show_components = false
```

避免 TradingView plot 數量過多。

### 9.4 命名

指標名稱建議：

```text
Shiori Fear & Greed Proxy
```

檔案命名建議：

```text
src/shiori_fear_greed_proxy_v0_2.pine
```

## 10. 校準計畫

v0.4 以前不追求精準校準，只追求方向合理與極端區域可辨識。

後續校準方式：

1. 對照 CNN 官網當日分數。
2. 對照 MacroMicro 或其他可視化歷史圖。
3. 測試 2020 COVID crash、2022 bear market、2023 AI rally、2024–2026 risk-on/risk-off 區間。
4. 調整 lookback、因子權重與反向標準化方式。

校準目標不是每日分數一致，而是 regime 大方向接近：

```text
Extreme Fear 是否大致出現在市場恐慌區
Extreme Greed 是否大致出現在風險偏好過熱區
Neutral 是否避免過度跳動
```

## 11. 與 Eddy 既有指標系統的關係

本指標定位為情緒層。

```text
Shiori Map              = 價格狀態 / 趨勢語氣
Macro Pressure Map      = 成長、通膨、政策壓力
Wyckoff Regime Radar    = 結構 / 吸籌 / 派發
Fear & Greed Proxy      = 群體情緒 / 風險姿態
```

此指標不應取代 Shiori Map 或 Macro Pressure Map，而是補足「市場情緒是否已經過度偏斜」這一層。

## 12. v0.2 Prototype 驗收標準

Codex 進行 v0.2 實作時，至少需要達成：

1. Pine Script v5 可編譯。
2. 成功計算 final 0–100 score。
3. 至少包含 Momentum、VIX、Safe Haven、Junk Bond 四個可穩定取得的因子。
4. 其他因子若 symbol 不穩，需允許 na 並透過 Auto Reweight 處理。
5. dashboard 能顯示總分、regime、有效因子數。
6. 程式中明確註解哪些因子為 CNN-like proxy，不是 CNN 原始算法。
7. 不得輸出買賣訊號。
8. 不得宣稱複製 CNN 官方指數。
